Documentation

Installation, common behaviour, and a reference for every subcommand: what it reads, writes and accepts. New to Scyros? Start with the tutorial, which runs a complete study step by step.

Installation

Scyros runs on macOS, Linux and Windows. The quickest way to install it is the installer script for your system.

macOS and Linux

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/fxpl/scyros/releases/latest/download/scyros-installer.sh | sh

Windows

In PowerShell:

powershell -ExecutionPolicy Bypass -c "irm https://github.com/fxpl/scyros/releases/latest/download/scyros-installer.ps1 | iex"

Cargo

Scyros is published on crates.io and requires Rust 1.93 or later. 

cargo install scyros

Nix

With flakes enabled:

nix profile install github:fxpl/scyros

Prebuilt binaries

The releases page provides archives for macOS (Apple silicon and Intel), Linux (x86-64 and ARM64) and Windows (x86-64, also as an MSI installer).

From source

git clone https://github.com/fxpl/scyros.git
cd scyros
cargo build --release

The binary is written to target/release/scyros.

Basics

A study is a chain of subcommands. Each subcommand reads a CSV file with -i and writes a new one with -o, so every intermediate result is a file that can be inspected, edited or shared. The reference lists the subcommands in the order a study usually runs them, as in the tutorial.

Two subcommands differ: ids takes no input file, and download writes its logs with -f and -p instead of -o. Without -o, the output file is named after the input file; each subcommand gives its default output name.

Resuming and overwriting

Subcommands that query GitHub (ids, metadata, languages, download and pr) resume where they stopped when rerun with the same arguments. With --force, they restart from the beginning instead.

All other subcommands refuse to overwrite an existing output file unless --force is set. Most subcommands also accept -f for --force, except download, where -f sets the file log.

Random seeds

ids samples at random, and metadata, languages, download, parse and pr process their input in a random order. Each uses a fixed default seed, listed in its options table, so a rerun gives the same result. -s sets another seed. In filter_metadata and duplicate_files, -s is a different option.

Global options

Global options go before the subcommand, as in scyros --debug parse ….

OptionDescription
--debugPrints debug messages and the causes of an error. With the environment variable RUST_BACKTRACE=1, also prints a stack trace.
-v, --versionPrints the version.
-h, --helpPrints help. After a subcommand, prints the help of that subcommand.

Getting help

This page lists every option of each subcommand. scyros <subcommand> --help describes the options of the installed version.

GitHub tokens

Subcommands that query the GitHub API take a CSV file of personal access tokens with -t. The file has a single column, token, with one token per line: 

token
ghp_first_token
ghp_second_token

Create a fine-grained token with access to public repositories only. Scyros only reads public data. The tutorial describes the steps.

One token is enough. Tokens from the same account share a single rate limit, so adding more does not speed up collection. Follow GitHub's rate limits and terms of service.

Never commit or share the tokens file.

Sampling

scyros ids

Samples public repositories at random. Each request starts from an ID drawn uniformly at random, with replacement, and returns the next 100 public repositories. Sampling stops once -n repositories are collected, rounded up to a multiple of 100. 

scyros ids -t tokens.csv -n 2000 -o ids.csv

Input: none, apart from the tokens file.

Output: one row per repository. No default name: -o is required. If the file exists, new rows are appended to it.

ColumnDescription
idRepository ID.
nameFull name, owner/repository.
fork1 if the repository is a fork, 0 otherwise.
request_numberRequest that returned the repository. Used to resume.

scyros forks

Removes forks. A fork duplicates the code of its parent repository, so keeping forks biases every later count. 

scyros forks -i unique_ids.csv -o ids_without_forks.csv

Output: the same columns as the input. Default name: input.non-forks.csv.

scyros filter_metadata

Keeps the repositories that meet thresholds on size, age and language. Popularity metrics such as stars and forks are deliberately not available as filters, because they bias the sample towards popular projects. Rows with an error instead of a name are always removed. Runs locally and sends no requests. 

scyros filter_metadata -i metadata.csv -s 50 -a 60 --non-code -o filtered_metadata.csv

Input: the output of metadata.

Output: the same columns as the input, except that created and pushed are replaced by age, the number of days between them. A negative age, caused by a wrong clock on the machine that pushed, is set to 0. Default name: input.filtered.csv.

Options

OptionDescriptionDefault

-aMinimum age in days, measured from creation to last push. Younger repositories are removed.0
--non-codeRemoves repositories without a primary language, such as those holding only documentation.Off
-dRemoves disabled repositories.Off
--no-outputPrints statistics without writing an output file.Off

Source code

scyros download

Downloads each repository at its recorded commit. It then deletes every file whose extension is not listed in the keyword files, and every file that contains no keyword. Keywords are matched anywhere in a file, including comments and string literals.

With --skip, download works on repositories already on disk instead of downloading them, and needs no tokens. 

scyros download -i java_go_repos.csv -t tokens.csv -k config.json -d repos -p projects.csv -f files.csv

Input: a CSV file with id, name and latest_commit columns, such as the output of filter_languages. With --skip, a path column instead of latest_commit.

Output: the downloaded files, a file log and a project log. The file log (-f) has one row per file kept.

The project log (-p) has one row per repository. Repositories that GitHub does not provide, such as deleted ones, and archives that cannot be extracted are logged as error rows.

scyros duplicate_files

Removes duplicate files, keeping one representative per group. Three strategies are available:

exact
Byte-identical files.
bow
Bag of words: the same tokens with the same frequencies, regardless of order and whitespace.
overlap
A large share of tokens in common. Also detects files that differ by a few statements, but is much slower.

exact and bow hash every file, so their cost grows linearly with the number of files. overlap compares files with one another, using the prefix filtering of SourcererCC to limit the number of comparisons. Two files are duplicates under overlap when the tokens they share reach --threshold times the token count of the longer file; a threshold of 1.0 requires the same tokens with the same frequencies. Files are only compared with files of the same language, given by the keyword files passed with -l: files whose extension is in none of them are left uncompared, and without -l every file is compared with every other.

Files larger than 1 GiB are ignored. Empty files form one group under exact and bow, and are each reported as unique under overlap. 

scyros duplicate_files -i files.csv -s bow -o unique_files.csv -m duplicates.csv

Input: a CSV file with a column of file paths (name by default), such as the file log of download.

Output: the same columns as the input, plus count, the number of files in the group. Default name: input.unique.csv.

The map (-m) has two columns: name (or the column given with --header), a file, and original, the representative of its group.

Options

OptionDescriptionDefault
-sStrategy: exact, bow or overlap.exact
-mMap of duplicates.input.duplicates_map.csv
-lOne or more keyword files, used only for their extensions and language names. Only used by overlap, which compares files within a language.None: all files are compared
--thresholdWith overlap, the share of tokens two files must have in common.0.8
-pWith overlap, maximum prefix depth. A deeper prefix rejects more candidates before comparing them in full. Only changes the running time, not the duplicates found.1
-nNumber of threads.1
--headerColumn of file paths.name

scyros parse

Parses each file with Tree-sitter and keeps the functions whose body contains at least one keyword. Comments and string literals are ignored. Each function is saved in its own file, named after its start line and column (such as 42-1), in a directory named after its source file with .functions appended.

Supported languages: C, C++, C#, Fortran, Go, Java, Python, Rust, Scala and TypeScript. The language of a file is given by its extension, as defined in the keyword files. Files in other languages are skipped with a warning. 

scyros parse -i unique_files.csv -k config.json -o functions.csv -l function_logs.csv

Input: a CSV file with id and name (file path) columns, such as the output of duplicate_files.

Output: one row per function kept. Default name: input.functions.csv.

Keyword files

A keyword file is a JSON file that lists the languages of a study and, optionally, the keywords to search for. It is read by filter_languages (-l), download (-k), parse (-k) and duplicate_files with -s overlap (-l).

Format

The top-level object has two fields:

languages
Required. A list with one entry per language. Each entry has the following fields:
name
Required. The language name as GitHub reports it, such as Java, Go, C++ or C#. Case-insensitive.
extensions
Optional. File extensions of the language, with or without the leading dot.
keywords
Optional. Keywords that only apply to files of this language.
keywords
Optional. Keywords that apply to every language.

filter_languages compares each name with the languages GitHub reports. parse uses it to select a parser.

Matching rules

  • By default, keywords match whole words and are case-insensitive: Thread matches Thread and thread, but not Threads or ThreadLocal. --case-sensitive makes matching case-sensitive.
  • Extensions are always case-sensitive: .c does not match main.C.
  • download matches keywords anywhere in a file, including comments and string literals. parse ignores comments and string literals.
  • A language with no keywords, neither its own nor top-level, keeps all its files and functions. Use this to study all the code of a language.
  • With --regex, each keyword is a case-insensitive regular expression and does not need to match a whole word. Use \b for word boundaries, and escape backslashes in JSON: "\\bAtomic\\w+" matches AtomicInteger and AtomicLong.

Multiple keyword files

download and parse accept multiple keyword files after -k. Each file produces its own column of matches, named after its path as given on the command line, so categories of keywords can be counted separately. A file or function is kept if it matches any of the keyword files. All keyword files must assign each extension to the same language. 

scyros parse -i unique_files.csv -k threads.json locks.json -o functions.csv
