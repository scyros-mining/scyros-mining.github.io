Documentation

How to install Scyros, the format of keyword files, and what each subcommand reads, writes and accepts. New to Scyros? Start with the tutorial, which runs a complete study step by step.

Installation

Scyros runs on macOS, Linux and Windows. The quickest way to install it is the installer script for your system.

macOS and Linux

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/fxpl/scyros/releases/latest/download/scyros-installer.sh | sh

Windows

In PowerShell:

powershell -ExecutionPolicy Bypass -c "irm https://github.com/fxpl/scyros/releases/latest/download/scyros-installer.ps1 | iex"

Cargo

Scyros is published on crates.io. This needs Rust 1.93 or newer. 

cargo install scyros

Nix

With flakes enabled:

nix profile install github:fxpl/scyros

Prebuilt binaries

Archives for macOS (Apple silicon and Intel), Linux (x86-64 and ARM64) and Windows (x86-64, also as an MSI installer) are on the releases page.

From source

git clone https://github.com/fxpl/scyros.git
cd scyros
cargo build --release

The binary is written to target/release/scyros.

GitHub tokens

Subcommands that call the GitHub API take a CSV file of personal access tokens with -t. The file has one column, named token, with one token per line: 

token
ghp_first_token
ghp_second_token

The tutorial shows how to create a token step by step. It only needs to read public information, so do not give it any permissions.

Never commit or share this file. Several tokens from the same account do not raise GitHub's limits. Please follow GitHub's rate limits and terms of service.

Keyword files

filter_languages, download and parse read keyword files, and so does duplicate_files with -s overlap. A keyword file is a JSON object with two fields:

languages
A list with one entry per language. Each entry has a name, a list of extensions (with or without the dot), and optionally a list of keywords that only count in files of that language.
keywords
Optional. Keywords that count in every language.

Write each language's name as GitHub writes it, such as java, go, c++ or c#. Capital letters do not matter. filter_languages compares the name with the languages that GitHub reports, and parse uses it to choose a parser. parse supports C, C++, C#, Fortran, Go, Java, Python, Rust, Scala and TypeScript.

How keywords match

  • A keyword matches whole words and ignores case. Thread matches Thread and thread, but not Threads or ThreadLocal. With --case-sensitive, Thread no longer matches thread.
  • Extensions always take capital letters into account: .c does not match a file called main.C.
  • download searches the whole file, comments included. parse ignores comments and string literals, so it is stricter.
  • A language with no keywords at all, neither its own nor shared, keeps every file and every function of that language. Use this to study all the code of a language.
  • With --regex, every keyword is a regular expression that still ignores case, but no longer has to be a whole word. Write \b where a word must start or end, and double every backslash in JSON: "\\bAtomic\\w+" matches AtomicInteger and AtomicLong.

Several keyword files

download and parse accept several keyword files. Each file gets its own column of matches, named after the file, so you can count categories of keywords separately. A file or function is kept if it matches any of them. The files must agree on which language each extension belongs to. 

scyros parse -i unique_files.csv -k threads.json locks.json -o functions.csv

Running steps again

  • After an interruption. The steps that call GitHub (ids, metadata, languages, download and pr) continue where they stopped when you run the same command again.
  • From scratch. The other steps refuse to overwrite an existing output file. Add --force to overwrite it, or to make a GitHub step start again from the beginning.
  • Default file names. Without -o, the output is named after the input: scyros forks -i ids.csv writes ids.csv.non-forks.csv.
  • Seeds. ids samples at random, and metadata, languages, download, parse and pr process rows in a random order. Each has a fixed default seed, which -s changes. In filter_metadata and duplicate_files, -s means something else.
  • Trying things out. --sub followed by a number makes metadata, languages, download and pr process only that many randomly chosen repositories.
  • Threads. parse and duplicate_files can use several threads with -n, and so can download with --skip.
  • All options. Every subcommand lists its options with --help, for example scyros parse --help.

All subcommands

A study is a chain of subcommands. Each one reads a CSV file and writes one, so every intermediate result is a file that you can inspect, edit or share. They are listed here in the order in which a study uses them, as in the tutorial.

For each subcommand, you will find what it does, an example, the columns it reads and writes, and its main options. Every subcommand also takes its input with -i (except ids), its output with -o (except download), and --force to overwrite an existing output. scyros <subcommand> --help lists every option of the version you have installed.

Sampling

scyros ids

Samples public repositories uniformly at random, with replacement. Each API request returns the 100 public repositories that follow a random id, until -n repositories are collected (rounded up to a multiple of 100). Without -n, it runs until you stop it.

scyros ids -t tokens.csv -n 2000 -o ids.csv

Reads: nothing but your tokens.csv.

Writes: one row per repository, with these columns.

ColumnMeaning
idRepository id.
nameFull name, owner/repository.
fork1 if the repository is a fork, 0 otherwise.
request_numberThe API request that returned it. Used to resume.

Main options

OptionWhat it does
-tThe tokens file. Required.
-oThe output file. Required.
-nHow many repositories to collect.
-sThe seed of the random sample. A fixed one is used by default.
--mode linearCollects repositories in order of id instead of at random.
--min, --maxThe range of ids to sample from. By default, every repository created until 5 January 2026.

scyros duplicate_ids

Removes rows with the same repository id, which sampling with replacement can produce. It prints how many it found.

scyros duplicate_ids -i ids.csv -o unique_ids.csv

Reads: any CSV file with an id column.

Writes: the same columns as its input.

Main options

OptionWhat it does
-cThe column to compare instead of id.
--no-outputOnly prints the number of duplicates.

scyros forks

Removes forks. A fork repeats the code of its parent repository, so keeping it would bias every later count.

scyros forks -i unique_ids.csv -o repos.csv

Reads: a CSV file with a fork column that holds 1 or 0, such as the output of ids.

Writes: the same columns as its input.

Main options

OptionWhat it does
--columnThe column to read instead of fork.
--no-outputOnly prints the number of forks.

Filtering

scyros metadata

Asks the GitHub API about each repository, one request per repository, in a random order.

scyros metadata -i repos.csv -t tokens.csv -o metadata.csv

Reads: a CSV file with id and name columns.

Writes: one row per repository, with these columns.

ColumnMeaning
idRepository id.
nameFull name, or an error such as http/2 404 if the repository was deleted or made private.
languageMain language according to GitHub. Empty if there is none.
created, pushed, updatedCreation, last push and last update, as Unix timestamps in seconds.
fork, disabled, archived1 or 0.
stars, forks, issuesNumbers of stars, forks and open issues.
has_issues1 if issues are enabled.
watchers_count, subscribersNumbers of watchers and subscribers.
sizeSize in kB.
licenseName of the licence, or unknown.

Main options

OptionWhat it does
-tThe tokens file. Required.
-cThe output of an earlier run. Repositories found in it are not asked about again.
--subOnly processes this many randomly chosen repositories.
--ids, --namesThe input columns to read instead of id and name.

scyros filter_metadata

Keeps the repositories that pass limits on intrinsic properties. Stars and forks are not used, since they would favour popular projects. Rows with an error instead of a name are always removed.

scyros filter_metadata -i metadata.csv -s 50 -a 60 --non-code -o filtered.csv

Reads: the output of metadata.

Writes: the same columns as its input, except that created and pushed are replaced by age: the number of days between them.

Main options

OptionWhat it does
-sThe minimum size in kB.
-aThe minimum age in days, between creation and last push.
--non-codeRemoves repositories without a main language, such as documentation only.
-dRemoves disabled repositories.

scyros languages

Asks the GitHub API for every language in each repository and for the SHA of its latest commit. download uses this SHA, which is what makes it reproducible.

scyros languages -i filtered.csv -t tokens.csv -o languages.csv

Reads: a CSV file with id and name columns.

Writes: one row per repository, with these columns.

ColumnMeaning
idRepository id.
nameFull name, or an error if the repository can no longer be reached.
languagesEvery language with its size in bytes, such as Go:80312;Shell:1022.
latest_commitSHA of the latest commit.

Main options

OptionWhat it does
-tThe tokens file. Required.
-cThe output of an earlier run, to avoid asking again.
--subOnly processes this many randomly chosen repositories.
--ids, --namesThe input columns to read instead of id and name.

scyros filter_languages

Keeps the repositories that contain at least one language of a keyword file, and removes those that can no longer be reached.

scyros filter_languages -i languages.csv -l concurrency.json -o selected.csv

Reads: the output of languages, and a keyword file.

Writes: the same columns as its input.

Main options

OptionWhat it does
-lThe keyword file, or a file with only a list of languages. Required.

Analysis

scyros download

Downloads each repository at its recorded commit, then deletes every file whose extension is not in the keyword files, and every file that contains none of the keywords. It writes a log with one row per file it kept and a log with one row per repository.

scyros download -i selected.csv -t tokens.csv -k concurrency.json -d repos -p projects.csv -f files.csv

Reads: a CSV file with id, name and latest_commit columns, such as the output of filter_languages.

Writes: one row per file, with these columns.

ColumnMeaning
idRepository id.
namePath of the file.
languageLanguage of the file, from its extension and the keyword files.
loc, wordsNumbers of lines and words.
keyword fileOne column per keyword file, named after it: the number of matches.

This is the file log (-f). The project log (-p) has, for each repository, its folder and its numbers of files, lines and words before and after the keyword filter.

Main options

OptionWhat it does
-kOne or more keyword files. Required.
-dThe folder to download into. Required.
-tThe tokens file.
-f, -pThe file log and the project log.
--countOnly computes the statistics, and deletes nothing.
--regexReads the keywords as regular expressions.
--case-sensitiveTakes capital letters into account when matching keywords.
--skipWorks on repositories that are already on disk, listed in a path column, instead of downloading them. -n then sets the number of threads.
--subOnly processes this many randomly chosen repositories.

scyros duplicate_files

Removes duplicate files, keeping one file from each group. Three criteria are available: identical bytes (exact, the default), the same tokens in any order (bow), or a large share of tokens in common (overlap), which also finds files that differ by a few statements but takes much longer.

scyros duplicate_files -i files.csv -s bow -o unique_files.csv -m duplicates.csv

Reads: a CSV file with a column of file paths, name by default, such as the file log of download.

Writes: the same columns as its input, plus count, the number of files in the group. The map (-m) has two columns: name, a file, and original, the file kept for its group.

Main options

OptionWhat it does
-sexact, bow or overlap.
-mThe map of duplicates.
-lKeyword files. With overlap, files are only compared with files of the same language.
--thresholdWith overlap, the share of tokens two files must have in common. 0.8 by default.
-nThe number of threads.
--headerThe column of file paths, instead of name.

scyros parse

Parses each file with Tree-sitter, and keeps the functions whose body contains at least one keyword, ignoring comments and string literals. Each function is saved in its own file, in a folder named after its source file with .functions added. Supported languages: C, C++, C#, Fortran, Go, Java, Python, Rust, Scala and TypeScript.

scyros parse -i unique_files.csv -k concurrency.json -o functions.csv -l function_logs.csv

Reads: a CSV file with id and name (the path of a file) columns, such as the output of duplicate_files.

Writes: one row per function, with these columns.

ColumnMeaning
idRepository id.
pathThe file that holds the function.
nameName of the function.
positionLine and column where it starts in its source file, such as 42:1.
languageLanguage of the source file.
loc, wordsNumbers of lines and words.
keyword fileOne column per keyword file, named after it: the number of matches.
loop_statements, loop_nestingsNumber of loops, and how deeply they are nested.
if_statements, if_nestingsNumber of conditionals, and how deeply they are nested.
functions_calls, function_calls_nestingsNumber of calls, and how deeply they are nested.
paramsNumber of parameters.
param_kw_matchNumber of parameters whose type matches a keyword.
return_kw_match1 if the return type matches a keyword.
parse_errorWhere the first parse error is, relative to the function, or none.

The log (-l) has one row per file: id, name, language, the number of functions and of functions_with_kw, one column per keyword file, and parse_error.

Main options

OptionWhat it does
-kOne or more keyword files. Required.
-lThe log file, with one row per file.
--countOnly computes the statistics, and does not save the functions.
--lambdasAlso extracts anonymous functions.
--regex, --case-sensitiveAs for download.
--failuresWhat to do with code that does not parse: ignore (the default), skip-file, skip-function or abort. Skipped files and functions get -1 in every column.
-nThe number of threads.

scyros pr

Collects the open, closed and merged pull requests of each repository. The discussion and review comments of each pull request are saved in a separate CSV file.

scyros pr -i selected.csv -t tokens.csv -d pull_requests -o pull_requests.csv

Reads: a CSV file with id and name columns.

Writes: one row per pull request, with these columns.

ColumnMeaning
id, nameThe repository.
pr_numberNumber of the pull request.
file_pathThe CSV file with its comments.
user, user_idIts author.
created_at, updated_atTimestamps of creation and last update.
closed_at, merged_atTimestamps, or 0 if it was not closed or merged.
draft1 if it is a draft.
stateIts state, such as open or closed.

Each comments file has id, user, user_id, type (body, discussion, code, review or error), created_at and body.

Main options

OptionWhat it does
-tThe tokens file. Required.
-dThe folder for the comments files. Required.
--subOnly processes this many randomly chosen repositories.
--ids, --namesThe input columns to read instead of id and name.
