Floating-Point Usage on GitHub

A Large-Scale Study of Statically Typed Languages

Tools that reason about floating-point arithmetic are usually evaluated on small benchmarks collected from earlier papers. We measured what floating-point code in public GitHub repositories actually looks like, and how well those benchmarks represent it.

How we mined the dataset

We mined the dataset with Scyros between October 2024 and March 2025. Uniform sampling gave us 125,234,729 unique repository ids. We removed forks and filtered projects on size, age and language, which left 447,209 projects with statically typed code. We then kept the files with floating-point keywords, removed duplicate files, and extracted and measured the functions in six languages. You can run the same pipeline to study other languages, other keywords or a newer sample of GitHub.

How common floating-point code is

We searched for floating-point keywords in four categories: floating-point types (e.g., float, double), transcendental functions (e.g., sin, exp), miscellaneous keywords (e.g., NaN, fmax, fma) and arbitrary-precision types (e.g., mpfr_t, BigFloat).

These are raw matches, that can be subject to false positives. After inspecting 385 files by hand, we estimate with 95% confidence that more than 62% of projects contain floating-point code.

Floating-point functions by language

We extracted 9,945,253 functions containing floating-point keywords from six languages. C++ and Java account for two thirds of them.

Which precision is used

Double precision dominates in Go and Java, and single precision in C++ and C#. A function can mention both, so the shares do not add up to 100%. We left out TypeScript, since it has a single number type.

Other precisions are rare: half precision appears in 2.7% of C functions and quadruple precision in 1.9%. Between 2.7% (C#) and 8.5% (Go) of functions mix precisions.

Use of mathematical libraries

The GNU Scientific Library (GSL) is another common evaluation target in the floating-point analysis literature. Among files with floating-point keywords, each GSL module appears between significantly less often than the C standard maths header, math.h.

Benchmarks from real code

As a case study, we extracted 59 self-contained C benchmarks from the dataset. Their median length is 30 lines, against 3 lines for FPBench, and they keep the constructs that benchmark suites usually leave out.
